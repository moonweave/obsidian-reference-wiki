# Names and note meanings

Display name: **Obsidian Reference Wiki**.
Korean description: **원문 근거를 남기는 문헌 지식 위키**.
Canonical skill: `obsidian-reference-wiki`.
Legacy invocation: `obsidian-research-wiki-reference` (compatibility package).

These are explanation labels, not a Vault migration or a schema rename.

| Stored note name/type | Korean explanation | Role |
|---|---|---|
| Paper / Source (`reference-record`) | 논문 노트 / 자료 노트 | One integrated reading record per external source. |
| Claim | 주장 | A bounded proposition reusable across sources. |
| Evidence | 근거 | A located result, observation or comparison supporting a claim. |
| Method | 문헌 방법 | Source-reported procedure, not the user's experiment protocol. |
| Theory | 이론·모델·기전 | A source-grounded explanatory framework and its assumptions. |
| Limitation | 한계·적용 범위 | What constrains a source or claim's interpretation. |
| Theme | 주제 지도 | A navigable synthesis of connected literature. |
| Question | 문헌 질문 | An open reading question, optionally followed by a grounded answer. |
| Source Text Manifest | 전문 파생본 출처 명세 | Provenance of a reading derivative, not another knowledge note. |

Use “literature record” / “문헌·자료 노트” as the umbrella for Paper and Source.
The term “Source” alone is reserved for a non-paper note when describing a
filename. Keep existing `Source — …` paper notes and citation-key basenames.

Keep detail in the literature record. Split out a knowledge note only for reuse,
an active question, independent revision or a distinct provenance boundary.
An open Question does not require that its reading candidates are already reviewed.
